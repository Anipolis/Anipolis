# 画面づくりの決まり（UX ガイドライン）

画面の改善で一度決めたことを残しておく文書です。同じ提案を何度も検討し直さないこと、画面ごとに判断がぶれないことが目的です。

- 外部のレビュー（Gemini など）を頼むときは、この文書も一緒に渡し、「この決まりと食い違う提案は、そのことを明記してください」と添えます。
- 決まりを変えるときは、この文書を先に直してから画面を直します。
- 見た目の土台（色・ボタンの種類・アイコン）の変更は Poti さんと相談します。

最終更新: 2026-10-26（ログイン・アカウント作成画面の見直し #497〜#504、初期設定・最初のホームの見直し #506・#507）

## 色と強調

- **青（`--color-accent`）は、その画面でいちばん押してほしい操作だけに使う。** 例: ログイン画面ではメールの「ログイン」「アカウントを作成」。Discord・Google・X などの外部サービスのボタンは、枠を灰色（`--color-border-hover`）・文字を本文の色にする（#498）。
- 補助の操作のボタンは `.btn-secondary`（灰色の枠・本文の色）を使う。画面ごとに `.btn-outline` を灰色に上書きしない。例: 外部サービスのログイン、「画像を変更」、自分のプロフィールの「プロフィールを編集」、はじめての人向けの案内、フォローした後の「フォロー中」「申請中」、フォローリクエストの「拒否」（隣の「承認」が青）。押せない状態の表示（「ブロック中」）も灰色にする。
- 選択中のタブは、色付きの背景と枠で示し、`aria-current="page"` を付ける（#497）。
- 色は `src/app.css` の変数を使い、色の値を直接書かない。ライト・ダークの両方で確かめる。
- テーマに合わせて `color-scheme` を切り替え、ブラウザが描く部品（スクロールバー・入力の部品）も暗く・明るくする（#514）。スクロールする欄は `.scrollbar-thin-muted` で細いバーにする。
- 文字と背景のコントラストは WCAG AA（通常の文字で 4.5:1）以上にする。※ダークテーマの青いボタン（`.btn-primary`）は今これを満たしていない（#500、Poti さんと相談中）。

## ブランドのロゴ

- ロゴの SVG は `src/lib/assets/brand/` に置き、`i-brand-*` のクラスで使う（#498）。
- 各社の決まりを守る: Google は 4 色の G のまま、X は黒か白（本文の色）、Discord は公式色（#5865F2）。
- ボタンの中では、ロゴを左端に固定し、文字は中央に置く。文字数が違ってもロゴの位置がそろう（#498）。

## 文言

- 作品を集めるものは3つあり、名前で区別する: 「マイリスト」は視聴の記録（視聴中・完了など）、「ベスト作品」はプロフィールに飾る10作品、「コレクション」はテーマを決めて人に見せるまとめ（#515）。コレクションを「リスト」と呼ばない（マイリストと紛れる）。
- 呼び方をそろえる: 丸い自分の画像は「アイコン画像」、横長の画像は「ヘッダー画像」（「プロフィール画像」はどちらか分からないので使わない、#514）。

- **ボタンは「押すと何が起きるか」が分かる言葉にする。** 手続きの名前（「確認」など）にしない。例: 招待コードの「次へ」。
- 同じ画面にタブがあるときは、タブで言い分ける。例: ログインのタブは「Discordでログイン」、アカウント作成のタブは「Discordで登録」（#503）。「〜で続ける」はどちらのタブか分からないので使わない。
- 見れば分かる補足（「招待してくれた方から届いたコードです」など）は書かない。説明文より、小見出しで区切る方を選ぶ（#497）。
- 長い説明文の代わりに、状況だけを短いバッジで示す。例: 「クローズドβ」（#497）。
- 絵文字は使わない。

## 入力フォーム

- **ブラウザやパスワード管理ソフトが自動入力する欄（メールアドレス・パスワードなど）があるフォームでは、未入力のときにボタンを押せなくしない。** 自動入力された値は、利用者が画面を触るまでページから読めないことがあり、入力済みに見えるのに押せない状態になる。空のまま送られたら、エラーを出して空の欄にフォーカスを戻す（ログイン画面で見送った提案）。
- 自動入力されない欄（招待コード、初期設定で新しく決めるユーザー名など）は、空の間ボタンを押せなくしてよい（#497・#506）。
- ラベルを画面から消すときも、読み上げ用（`sr-only`）には残す。プレースホルダーは入力を始めると消えるため、ラベルの代わりにならない（#497）。
- 入力例のプレースホルダー（「アニメ太郎」など）は置かない。入力済みの値に見えて、空欄だと分かりにくい。書き方は欄の下の補足で伝える。例外: ラベルを隠した欄の「招待コードを入力」のように、何の欄かを示すもの（#510）。
- 形式や大きさの決まり（「JPEG・PNG・WebP、最大10MB」など）は画面に書かず、外れたものが選ばれたときだけ赤字で伝える（#510）。
- 入力の間違いで戻ってきたときは、入力した内容を残し、直すべき欄にフォーカスを移す。
- エラーは、送ったときの値のままの間だけ出す。直したら消す。エラー中の欄は `aria-invalid` を付け、枠もカーソルの枠も赤にする（赤と青を二重にしない、#506）。
- 確認済みの値（確認できた招待コードなど）は、入力欄にせず「○○を確認しました」の 1 行にする。変えたいときは前の画面からやり直す（#497）。
- 新規登録で入力させるのは最小限にする。ユーザー名・表示名・アイコンは登録後の初期設定画面で決める（#499）。
- パスワードは 8 文字以上（`MIN_PASSWORD_LENGTH`、#502）。
- 画像を選ぶ場所では、プレビュー（アイコン・ヘッダー自体）を押しても選べるようにする。キーボードの移動先と読み上げは「画像を変更」のボタンだけにする（プレビューは `aria-hidden` の label、#510・#514）。
- 選んだ画像は、使う範囲を決める画面（`ImageCropper`）を通してから使う。アイコンは丸（正方形 512px）、ヘッダー画像は 3:1（1500×500px）。表示も同じ比率にして、決めた範囲がそのまま見えるようにする（ヘッダーはスマホでも 3:1）。元の画像は 10MB まで選べる
- 画像のボタンは、画像が無いときは「画像を選択」、あるときは「画像を変更」と、外すための「削除」。丸いアイコンは左、ボタンは右に並べる（初期設定・プロフィールの編集、#514）。
- 外部サービスから持ってこられる値（名前・アイコン）は、最初から入れておく。入っているものは「変更」で置き換え、外したい人のために「削除」を置く。外部サービス専用のボタン（「〇〇のアイコンを使う」など）は作らない（#506）。
- 送信ボタンは、スマホ幅では横幅いっぱいにする（ログイン・初期設定）。

## 画面の移り方

- **入力中の内容を失わせない。** 規約などを読ませるときは、新しいタブで開かず、今の画面の上に重ねて開く（shallow routing）。ブラウザの「戻る」・Esc・×で閉じられるようにする（#501）。
- 新しいタブで開く外部リンクには ↗ のアイコンを付け、読み上げ用に「（新しいタブで開く）」を添える。
- 複数の手段から 1 つを選ぶ画面では、手段を同じ並びのボタンにする。1 つを選んだら他のボタンは隠して、その手段の入力だけにし、「← ほかの方法で〜」で戻れるようにする（#503）。
- 行き止まりを作らない。条件を満たさない人（招待コードが無い人など）には、次に取れる行動を控えめに示す（#497）。

## 一覧から選ぶ画面

- 検索して選ぶモーダルでは、検索欄を上に固定する。検索欄に文字がある間は、下の場所を検索結果に切り替える（選んだ一覧を押し広げない）。モーダルの高さは固定し、追加しても行の位置をずらさない（#516 の後の見直し）。
- 検索結果は行全体を 1 つのボタンにする。「追加」は青にしない。追加済みの行は押せなくして「選択済み」と出す。
- 同じ名前の作品を見分けられるよう、題名の下に「2018年・TV」のような補足を薄い色で添える。カバーが無いときは、アイコン入りの同じ大きさの枠を出す。
- 選べる数に上限があるときは、見出しの横に「3 / 10」と出す（上の「形式や大きさの決まりは書かない」は入力欄の話で、選ぶ数はこれに当たらない）。
- 検索中の Esc は検索をやめるだけにし、もう一度押したら閉じる。
- 横に並べる一覧は一列にし、スクロールバーは出さない。マウスの画面では左右の送りボタン（続きがある側だけ）で、スマホでは指で送る。折り返して2段にすると、件数によって2段目が中途半端に空く（ベスト作品は10件で、1段6件）。

## はじめての人

- まだ何もしていない人（フォロー 0・マイリスト 0 など）には、最初にやることを控えめなカードで示す。ボタンは灰色の枠、× で閉じられ、閉じたらその端末では出さない（#507）。

## 端末に覚えさせること

- 前回使った手段など、利用者の手間を減らす情報は、端末（Cookie）に名前だけを覚えさせてよい。個人情報は入れない。並び順は変えずに印だけ付ける（#504）。
- 「閉じた」などの見た目の好みは localStorage に覚えてよい。読めない環境でも画面が正しく出るようにする（#507）。

## 自分の表示

- 自分のアイコンの頭文字は、どこでも表示名から出す（無ければユーザー名）。画面によって「A」と「ア」のように食い違わせない（#507）。

## アクセシビリティ

- `autofocus` は使わない（検査で禁止）。開いたときにフォーカスを移したいときは、利用者の操作（ボタンを押した）をきっかけに移す。
- 重ねて出す画面（モーダル）は、フォーカスを中に閉じ込め、閉じたら元の場所に戻す（`trapFocus`）。
- アイコンだけのボタンには `aria-label` を付ける。

## 見送った提案（理由つき）

| 提案 | 見送った理由 |
|---|---|
| ログイン・アカウント作成のボタンを、未入力の間は押せなくする | 自動入力と相性が悪い（上の「入力フォーム」） |
| ログインとアカウント作成のタブを 1 つにまとめる | メールの登録とログインで入力項目が違う |
| ボタンに「（サーバー参加者限定）」のような括弧書きを付ける | 小見出しで伝わり、スマホ幅で折り返す |
| 確認済みの招待コードに「変更」ボタンを付ける | 確認するボタンが無く行き止まりになる。前の画面からやり直せばよい |
| 招待コードが無い人のためのウェイティングリスト | Discord サーバーへの案内で足りる（必要になったら別途検討） |
| 初期設定の途中でメニュー・サイドバーを隠す | すでにロゴ・テーマ切り替え・アカウント（ログアウト）だけになっている。ログアウトは逃げ道として残す |
| ベスト作品の並べ替えをドラッグでもできるようにする | 10件までなので上下のボタンで足りる。スマホではスクロールとぶつかって誤操作のもとになる |
| 作品を追加したらトーストを出す | 押した行がその場で「選択済み」になり、件数も増える。一覧に戻ったときに足した行を軽く光らせる |
| スマホのホームの上の投稿欄をやめて右下のボタンにまとめる | ホームの配置の話なので Poti さんの判断待ち（#508） |
